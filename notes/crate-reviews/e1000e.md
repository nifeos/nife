## In one paragraph

The logic of a driver for Intel's e1000e family, as pure computation: the 82574L that QEMU's
`-device e1000e` presents and the Sunrise Point I219. `no_std`, no allocator, no `unsafe`, no run-time
dependency. The caller supplies volatile register access and DMA memory behind four small traits;
the crate computes everything else (offsets and bits, descriptors, the DMA region's layout, the
receive and transmit rings, the I219 bring-up). Kani proves three properties and each has a
falsification patch. Every gate passes. What remains is the architect's ruling on the names below
and the clearance to move it.

## API

- Root: `DataPlane` (`new`, `start`, `receive`, `transmit`, `can_transmit`, `receive_cursor`,
  `set_receive_tail`, `set_transmit_tail`), `DirectMemoryAccessRegion` and `Tails` (the caller's
  half), `ReceiveVerdict` with `receive_verdict`, `TransmitError`, the descriptor constants, the
  control-register values and `station_address_from_receive_address`, and the device table
  (`DEVICE_IDS`, `VENDOR_INTEL`, `is_supported_device`, `model_name`).
- `registers` and `layout`: BAR0 offsets and the DMA region's offsets, each a spelled-out constant.
- `platform_controller_hub` (alias `pch`): the I219 bring-up behind the `Hardware` trait. `sequence`
  (`initialize_hardware`, `global_reset`, `setup_copper_link`, the errata), `flush`
  (`empty_descriptor_rings`, `FlushSupport`, `EmptiedRings`), `physical_layer_device` (management
  data input and output access behind a held `SoftwareFlag`), `non_volatile_memory`, `ultra_low_power`
  and `reset`.
- No nife type, capability or handoff appears in a public signature. `cargo tree` lists no
  dependency.

## What is surprising in the API

- Every error enum (`TransmitError` and the four `Error` types) now implements `Display` and
  `core::error::Error`; `sequence::Error` reports its wrapped errors as the source.
- `Hardware::note` receives a `BringUpObservation`, an enum for printing, not matching.
  It is `#[non_exhaustive]`, so a match needs a wildcard arm.
- `SoftwareFlag` has a private field, so only `physical_layer_device::acquire` makes one. It proves
  it holds the flag; it does not release on drop. `release` consumes it.
- `PagedAccessPlan` has public fields and is `#[non_exhaustive]`: a caller reads a plan and cannot
  build one.
- Raw `u32` and `u64` values stand for register contents, as in every register crate here.

## Proofs

| harness | what it proves |
|---|---|
| `proofs::a_delivered_frame_always_fits_the_buffer_and_the_room` | for every status word and buffer size, a frame `receive_verdict` delivers fits both |
| `proofs::every_ring_offset_is_inside_the_region` | for any index, every descriptor and buffer offset lies inside its part of the DMA region |
| `platform_controller_hub::physical_layer_device::proofs::a_paged_access_selects_the_offsets_own_page_and_register` | a paged access names an address that exists, the offset's own register and its own page |

Not proven: the non-volatile memory reads (device-supplied input, the first candidate for a fourth
harness), the reset, ultra low power and
physical layer workaround sequences (ordered writes), and transmit descriptor status. Host tests against a simulated device cover them.
