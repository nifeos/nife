# The manual: resolved BUGS entries

*Name: provisional.*

An appendix to [`notes/documentation.md`](../documentation.md), whose `BUGS` section now carries
only what is still true. These entries are resolved and kept for their reasons.

## `mdr <page>` on its own was refused

DECISIONS §106 (take the `terminal_sink_caretaker` narrowing), 2026-08-22, closed it, and it now
renders. It deadlocked when phase 1 shipped. From milestone 50 (pipes and redirection) and its chain
check onward it was a refusal that named the fix, and this entry described that refusal until this
line. The mechanism is exactly what it named as the fix. An unredirected tail stage's primary output
now defaults to `terminal_sink_caretaker`, the terminal's own sink adapter. That is the same one a
declared second stream already reached by default under DECISIONS §67 (a program's second stream is
a declaration). `grant_plan::check_chain` still refuses a redirected shape that has nowhere for the
shell to wait but itself (`mdr <page> > out.txt`). It is only the unredirected, screen-bound case
this decision narrows:

```text
$ mdr gate.txt
  hello world hello world
```

The constraint underneath is the kernel's rather than the shell's, and it is worth reading before
reaching for a scheduling fix. A process has one wait point. `SEND` blocks until a receiver takes
the message, `RECEIVE` blocks until one arrives, and there is no select and no timed wait. So a
shell feeding a chain cannot be receiving from it, and no interleaving schedule fixes it.
Alternating one send with one receive deadlocks whenever the stage reads twice before it writes. The
other way round deadlocks whenever it writes twice before it reads. The shell cannot know which,
because the whole point of the sink contract is that neither end knows anything about the other.
What changed is not the schedule. The tail's reader is no longer the shell at all, so the shell was
never the thing the chain needed to wait behind.

Before the decision was made, the `BUGS` entry on the caretaker hop flagged its cost as "a stage
that outlives its command can paint a prompt nobody typed". The main page now names it precisely, as
a display race.

## `mdr <page> | wc` and `mdr <page> > out.txt` deliver the file now

Both answered `0 0 0` when phase 1 measured them. A pipeline's head was wired off the `Line`, which
carries no `<`, so the planned input operand was dropped and the stage counted an empty stream.
That was fixed in `components/src/swish.rs`, where the head's input now comes off the plan. The fix
is pinned at the real prompt on both architectures:

```text
$ wc gate.txt
  2 4 24
$ mdr gate.txt | wc
  1 4 26
```

Two source lines are one paragraph re-flowed to one output line, and the two extra bytes are the
body indent. So the counts are what separate a rendered page from silence. `MAX_TEXT_CHUNKS = 32`
was the other half of this entry and is also gone. The shell drains `MAX_OUTPUT_CHUNKS = 4096`
messages, which is 64 KiB rather than 512 bytes.

## Ranking was occurrence count and nothing else

It divides by document length now (2026-08-22). The page record grew a `tokens` field, spent out of
the six bytes it already held spare. `documentation::index::Ranked::offer` ranks by `count / tokens`
(fixed-point, one division) rather than by raw `count`. A short page where a term is dense now
outranks a long page where it is only mentioned in passing, even with a smaller raw count.
`Found::count` still reports the raw occurrence count in the printed answer; only the order changed.
`apropos capability`'s own answer over this store did not reorder, because the strongest page for
that term is also the densest one. `index::VERSION` moved to 2 for the format change. Every shard
is a build artifact regenerated by `cargo xtask manual`, so there was nothing to migrate.

The host example's order is no longer sorted by its first column. That is the ranking increment
showing itself rather than a bug in the example. `notes/pipes.md` has the second-highest raw count
(32) but the lowest density, because it is the longest page in the `swish` bundle.
`notes/ipc-naming.md` outranks it with a third of the mentions because it is short. `Found::count`
still prints the raw number honestly; only the order it appears in changed.

## What used to head "Where this goes next"

The guest-side `apropos` that used to head this list is built (phase 2), and it went to the builtin
the entry predicted. The spawn-protocol decision that used to head this list is also built
(DECISIONS §106, 2026-08-22). `mdr <page>` renders at the prompt with no `| wc` in front of it. The
caretaker-hop race it flagged before the decision was made is a named, accepted interim rather than
a surprise. Both are recorded in the main page's `BUGS` section now rather than there. The third
ranking item there is built too (2026-08-22, same day), and this page says what changed.
