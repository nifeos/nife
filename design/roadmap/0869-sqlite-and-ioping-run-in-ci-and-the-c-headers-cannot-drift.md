# 869. SQLite and ioping run in CI, and the C headers cannot drift

*(Minted 2026-10-10 (UTC) by lane `milestone/835-a-c-library-stage-one-files-clock-and-memory`
from calef's rulings on #1896 the same day; the number is provisional until the merge queue lands
it. The title and slug are drafts.)*

calef ruled two questions on #1896 (2026-10-10 UTC). Q3: CI fetches SQLite and ioping, as #1853's
`rg` rows do, inside the merge group's 20-minute budget. Q2, option B: the cbindgen headers stay
committed. CI regenerates them and fails on any difference, the shape rustls-ffi uses.

## Why

Milestone 835 (a C library, stage 1: files, clock and memory) runs SQLite's `speedtest1` and ioping
unmodified on all three architectures. Its tests skip unless their helpers ran, so CI checks
neither. That is the gap fatal risk 1 recorded for `rg` until #1853 closed it. The C headers in
`vendor/relibc/include/` are generated by hand. An edit to a seeded module's exported types can
leave them stale, and nothing says so.

## What it builds

- CI rows that run `helpers/build-speedtest1.sh` and `helpers/build-ioping.sh`. Their downloads
  are already pinned by SHA-256.
- Then the three `c_program_tests` on each architecture, refusing to skip in CI, as #1853's rows
  refuse for `rg`.
- The fetch and build fit the merge group's 20-minute budget. If they do not, the block says what
  was measured and which rows move to the pull-request run.
- A drift check. CI installs cbindgen 0.29.0 and runs `helpers/c-library-headers.sh`. Any `git
  diff` under `vendor/relibc/include/` fails it.

Reuse: #1853's `swish-check` rows for the shape, and the two helpers and the header script as they
are.

## Done when

A pull request fails CI if it breaks either program. It also fails if it changes a seeded module's
exported types without regenerating the header.

## Index row

SQLite's `speedtest1` and ioping built and run in CI on all three architectures, as `rg` is, and a
check that regenerates the C library's headers and fails on drift.
